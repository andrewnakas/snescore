# Licence audit of the earlier (recompilation) builds

Audited 2026-10-08 on the DKC1 tree: `elliotttate/DKC1Recomp` at `3eb9a10c49cb210df2bd63addafe2a78cf9f4e22`
with its `snesrecomp` submodule (`elliotttate/snesrecomp`, a fork of `mstan/snesrecomp`) at
`de94587464524ebac8dcd62e14618bf0d3953644`. DKC2Recomp (`3b386cb`, submodule `3a929cd`) and DKC3Recomp
(`3a033f1`, submodule `3b24b9d`) have the same structure and the same licences and were spot-checked only.

Method: licence files, git history, file headers, the list of objects in the web build directory, undefined
symbols of the generated objects (`llvm-nm -u`), and line-overlap statistics. PolyForm-licensed source bodies
were measured mechanically and not read for content.

## History of the snesrecomp licence

## Provenance of the hardware files

snesrecomp's README credits snesrev (zelda3 / smw) for the runner and LakeSnes for PPU/DSP. Both are MIT
(licence texts fetched from the repositories: LakeSnes "Copyright (c) 2021-2023 angelo_wf and contributors";
smw "Copyright (c) 2023 snesrev, Copyright (c) 2021 elzo_d"; zelda3 likewise).

Conclusion: the hardware files started as verbatim copies of snesrev/smw (MIT, itself derived from LakeSnes),
and have since been rewritten heavily under PolyForm. **A clean MIT upstream exists** for CPU, PPU, APU, SPC700,
DSP, DMA and cart: LakeSnes itself. The current snesrecomp copies cannot be used, and need not be.

## Is the generated game C usable commercially? No.

Three independent reasons, any one of which is enough:

1. **It is the game.** The generated C is a mechanical translation of the cartridge's 65816 program. The
   generator's own README says it is derived from the ROM and must not be redistributed without permission;
   DKC1Recomp itself does not distribute it. Changing the runtime's licence does nothing about this. (The old
   wasm contains 0 verbatim ROM byte windows per `romscan.py`, but a translation of the program is still the
   program.)
2. **It compiles PolyForm code in.** Every generated file includes `cpu_state.h` (705 lines, 26 `static inline`
   functions), `cpu_trace.h` (1,416 lines, 71 `static inline` functions) and `common_cpu_infra.h` from the
   PolyForm runtime. Inline functions from those headers are compiled into every one of the 2,174 objects.
3. **It is written against the PolyForm runtime's private protocol.** Besides plain memory access
   (`cpu_read8/16`, `cpu_write8/16`), the generated objects call about 20 runtime-internal functions whose
   meaning is defined only by the PolyForm source: `interp_bridge_lle_yield_unwind`,
   `interp_bridge_lle_master_deadline_reached`, `interp_tier_dispatch`, `interp_tier_dispatch_rewritten_return`,
   `interp_tier_dispatch_popped_return`, `interp_bridge_return_targets_owner`,
   `interp_bridge_has_direct_paired_bounce`, `cpu_resolve_ancestor_skip`, `cpu_dispatch_pc_from`,
   `cpu_dispatch_has_entry`, `interp_tier_run_call_frame`, `cpu_take_tailcall_return_context`,
   `cpu_tailcall_inherit_return_context`, `RecompStackPush/Pop`, `WatchdogCheck`, ... (each referenced by
   1,300-2,174 of the files). Re-implementing those faithfully without reading the PolyForm source is not a
   clean re-declaration of an interface; it is re-deriving the runtime's design.

   Also, the emitted text repeats the generator's own templates in every function (prologue, yield checks,
   return-context handling). Whether that boilerplate carries the generator's copyright into its output is a
   legal question this audit does not answer (inferred risk, not verified).

## Consequence

A "MIT runtime underneath the same generated C" would still ship (1) and (2), so it was not built.
What was built instead removes the generated code together with the runtime: an MIT SNES machine
(`snescore`, on LakeSnes) that runs the ROM the person supplies. See the README.

Alternatives that were considered and not taken:

- Ask the snesrecomp author for a commercial licence. Solves the runtime, not reason 1.
- Write a new recompiler and runtime from scratch. Solves the runtime and the templates, not reason 1.
- Keep the recompilation builds for non-commercial use (they are fine as they are under PolyForm NC) and
  use this repository where a commercial-compatible licence is needed.
